# Phase 3 設計 — データ生成・1 kHz 変換・検証・出力（issue #19）

作成: 2026-10-12 / 状態: **叩き台（承認待ち）**。J2 版（`j2-state-data-gen` の `genJ2Dataset`, `j2Downsample`, `j2ExportFlat`, `j2Coverage`）を参照した。

## 1. 要件（FR-3〜FR-7 の具体化）
| 項目 | 要件 |
|---|---|
| 生成 | `saScenarioSet(3,'full')` の 158 本を 8 kHz で全件実行。シナリオ単位でキャッシュし、中断しても続きから再開できる |
| 分担 | Parallel Computing は使えないため、別プロセスで shard を指定して分担する（J2 版と同じ）。このマシンは 4 コア・メモリ 13 GB。1 プロセス約 3.7 GB なので、同時に 2〜3 本 |
| 1 kHz 変換 | 状態は瞬時値の間引き（フィルタなし）。トルクは区間 [t_k, t_k+1] の**台形平均**（Phase 1 の決定。J2 版の単純平均とは違う）。遷移 `(x_k, τ_k) → x_{k+1}` |
| split | シナリオ単位（Phase 2-3 で決定済み。train / val / test / benchmark）。正規化統計は train のみ |
| 検証 | 有限性、トルク・速度・角度の範囲、split のリーク、解析モデル（RNEA＋摩擦）との 1 ステップ整合、全シナリオの再現性 |
| カバレッジ | 軸別の位相平面、トルク分布、周波数、PTP の包含率。状態が 6 次元（3 軸）なので占有率は使えず、軸別の 2 次元占有＋正規化 6 次元空間のボクセル占有で見る（Statistics Toolbox の kNN は使えないので自前） |
| 出力 | HDF5（h5py から (N,d)、ID は 0 始まり）。MATLAB 側は v7.3 mat |
| 再現性 | キャッシュなしの再生成でビット一致を確認 |

## 2. 設計の決定点（案）
1. **キャッシュは double で保存する**（J2 版は single）。3 軸 full の 8 kHz 生データで約 0.75 GB と小さく、再現性のビット比較を単精度の丸めに邪魔されない。HDF5 への出力時に single へ落とす
2. **遷移の定義**: 8 kHz のサンプル `i = 1 + 8k`（瞬時値）。τ_k は `i … i+8` の台形平均（端点が 1/2 の重み）。8 kHz 入力（FOH 補間）の実印加トルクを使う
3. **拘束フラグ**: 開始・終了状態のどちらかがリミットから 0.1° 以内または外側の遷移に `atLimit` を付ける（J2 版と同じ）。ソフトバリアだけの間は 0 に近いはず。Phase 3 の追加枠（接触）で効いてくる
4. **マニフェスト**: 生成条件、シード、親資産のコミット、MATLAB バージョン、シナリオ表のハッシュを保存
5. **モデル生成は shard ごと**（作業フォルダを分けて Simscape のキャッシュを分離。J2 版と同じ）

## 3. 計画（段階。Phase 2 と同じ「小さい issue に分ける」やり方）
| 段階 | 内容 | ゲート |
|---|---|---|
| 3-1 パイプライン | `genSaDataset`（キャッシュ・shard・再開）、`saDownsample`（台形平均）、組み立て（正規化統計・マニフェスト）、`validateSaData`。small プリセット（20 本）で一通り通す。単体テスト（台形平均の解析値、遷移の整合、再開） | small で生成〜組み立て〜検証が通る |
| 3-2 3 軸 full 生成 | 158 本を shard 分担で全件実行。総時間・シナリオ別時間を記録。中断・再開の確認 | 全件が有限・範囲内で生成できる |
| 3-3 検証と評価 | 再現性（下記）、解析モデルとの 1 ステップ整合（RNEA＋摩擦、加速度換算の残差比）、カバレッジ評価（PNG は `reports/issue-N/`） | 再現性とカバレッジの結果が出ている（**ゲート G3、3 軸**） |
| 3-4 HDF5 出力 | `saExportFlat`（single、gzip）、h5py での読み戻し検証（Python 側の検証スクリプトのみ。学習は含まない） | h5py から (N,d) で読めて MATLAB と一致 |

| 3-6 6 軸 | 3 軸の総時間・カバレッジを見て件数を見直し、6 軸 full を生成・検証 | G3 を 6 軸でも満たす |

各段階を 1 issue・1 PR とする（3-1 は #19 で行う）。

## 4. 見積もり（実測前）
- 3 軸 full の継続時間の合計は 1,290 s（PTP は 30 s の上限で数えた値）。励振は実時間の約 15 倍なので、シミュレーションだけで約 5.4 時間（直列）、シナリオごとの Simscape のコンパイル（10〜15 s × 158 本 ≒ 30 分）を足して**直列で約 6 時間**。3 shard なら約 2 時間台の見込み
- 6 軸は励振が約 31 倍で、件数が同じなら約 2 倍＋α。**実測してから**判断する
- データ量: 約 1.2 × 10^6 遷移（3 軸）

## 5. 再現性の確認方法（案）
全件のキャッシュなし再生成は 3 軸で約 6 時間かかる。次の 2 段にする。
1. **同一セッション・別プロセス**で、各パターンから 1〜2 本（約 25 本）を再生成してビット一致を見る
2. 余裕があれば全件。Phase 3-2 の全件生成を 2 回目に回す必要があるため、**全件は 3-3 で夜間に回す**

## 6. 未決・要確認
1. 再現性は上記の 2 段（約 25 本の抜き取り→全件）でよいか
2. 接触シナリオ（3-5）は、3 軸の基本データセットが通ってから設計する、でよいか
3. shard 数は、メモリ使用量を見て 2 または 3 にする。他の作業と同時に回す場合は 2 とする
