# Phase 4-3b 報告: 計算の高速化の観点での学習モデルの優位（issue #39）

## 方法
- 全方式を (q, dq, tau) → 次状態（1 ms 進める）の同じ関数にして、PyTorch（CPU 4 コア、スレッド数 4 と 1）で時間を測る。バッチ 1（レイテンシ）〜65,536（スループット）。ウォームアップ 3 回、0.6 s 以上の反復の平均。実装: `python/bench_speed.py`、集計 `python/summarize_speed.py`、全表 `reports/issue-39/speed_tables.md`、図 `reports/issue-39/speed.png`。
- 解析モデル: Python 版（`sa_nsm/physics.py`、RNEA、RK4、サブステップ 1/2/4）。参照として MATLAB `saFwdDyn` も測った（1 回 2.23 ms、1 ステップ = 加速度 8 回の概算 17.9 ms）。
- NN: 4-2 本番のシード 0（A: 純 MLP、B/C: 解析モデル + 残差。B/C は解析モデルの計算を含む）。
- Simscape（真値）: 生成の実時間 7,688 s ÷ 遷移数 1,289,294 = 約 6.0 ms/ステップ（8 kHz で 8 ソルバステップ。Simulink の起動・コンパイルを含むので上限寄りの値）。

## 結果（4 スレッド、1 ステップ当たりの時間 [ms]）
| 方式 | バッチ 1（レイテンシ） | バッチ 256 | バッチ 4,096 | バッチ 65,536 |
|---|---|---|---|---|
| 解析 RK4 サブステップ 1 | 17.8 | 0.147 | 0.080 | 0.046 |
| 解析 RK4 サブステップ 2（データ生成と同じ） | 34.8 | 0.287 | 0.137 | 0.092 |
| NN A（純 MLP） | 0.191 | 0.052 | 0.0065 | 0.0070 |
| NN B（解析 + 残差） | 36.6 | 1.37 | 0.444 | 0.139 |
| NN C（ゲート付き） | 40.4 | 0.275 | 0.125 | 0.096 |
| Simscape（参考） | 約 6.0 | | | |

1 スレッドでもほぼ同じ傾向（A のレイテンシ 0.20 ms、解析サブステップ 2 は 34.2 ms）。

## 精度との対応（test の自由運動、1 ステップの加速度換算 RMSE [rad/s²]、J1/J2/J3）
- 解析 サブステップ 1: 0.014 / 0.024 / 0.030、サブステップ 2: 0.013 / 0.007 / 0.013、サブステップ 4 以上は変わらない（0.013 / 0.005 / 0.012）。
- NN A: 4.9 / 5.9 / 10.8（約 400〜900 倍悪い）。窓評価（4-3）でも、自由運動の 200 ms 後の速度誤差は解析 1e-4 に対し A は 0.3〜0.7 rad/s で、状態維持（0.9〜1.4）の 3 分の 1 程度に過ぎない。

## 所見
1. **NN A は速い**: レイテンシは解析 RK4（サブステップ 1）の約 1/90、Simscape の約 1/30。大バッチのスループットは解析（サブステップ 2）の約 14 倍（0.0065 対 0.137 ms/ステップ、バッチ 4,096）。
2. **しかしその速度は精度と引き換えで、使えない**: 自由運動の誤差が解析モデルの 400〜900 倍。解析モデルは、サブステップを 1 に減らして時間を半分にしても精度はほぼ変わらない（加速度誤差 0.01〜0.03 rad/s²）ので、速度が要る場合は NN ではなく解析モデルの簡略化（サブステップ 1）が先に選ばれる。
3. **B・C は高速化にならない**: 解析モデルの計算を含むため、解析モデル以上に速くならない（B は NN の追加で遅くなる）。
4. **留意（重要）**: 解析モデルの実装（Python の RNEA、MATLAB の `saFwdDyn`）は最適化されておらず、1 ステップ 18〜35 ms と **Simscape（約 6 ms）より遅い**。3 自由度の動力学を C/コード生成・事前計算で最適化すれば大幅に速くなる見込みだが、今回は未測定で、倍率は主張できない。NN A の速度優位は、「現在の（未最適化の）解析モデルに対して」の値である。
5. NN の側も、PyTorch の Python オーバーヘッドが支配的（バッチ 1 で約 0.19 ms）で、C++ への書き出しなどで速くなり得る（未測定）。

## 結論と次の作業
- 現状の精度では、計算の高速化の観点でも学習モデルの優位は無い（A は速いが精度が足りず、B/C は速くならない）。
- 速度が価値を持つのは、(a) NN の精度が解析モデルに近づく場合、または (b) 接触・摩擦など、解析モデルが遅い／不正確な領域の代替として使う場合。(b) は 4-3 の切替方式（リミット近傍のみ B）で、NN を使うステップが 9〜20% に留まるため、速度への寄与は小さい。
- 公平な比較のため、先に解析モデルを最適化（コード生成など）して再測定する案がある（別 issue の候補）。
