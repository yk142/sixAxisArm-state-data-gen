## 見つかったこと
1. **トルクが変化すると速度が瞬間的にジャンプする（armature の RMI が原因）。** 当初「初期過渡」と書いたが、t=0 に限らない。切り分け（`spike/phase1_transient.m`、`phase1_kick.m`、`phase1_stepcheck.m`、`phase1_pwc.m`。6 軸、静止から重力補償＋手首ステップ）:
   - armature なしのモデルは解析モデルと 1e-10 rad/s で一致し、過渡もない。**armature ありのときだけ**起きる。
   - 起きるのは「正味トルクが変わった瞬間」。重力補償のみ（正味 0）で t=0 から始めると出ない。保持の途中（t=10 ms）で J6 に +2 N·m を足しても出る。
   - 速度ジャンプの大きさは **Δτ（正味トルク変化）× 約 1 ms ÷ 実効慣性**（J6: 実測 0.1203 rad/s、予測 0.1208）。つまりプラントの応答が解析モデルより約 1 ms 進んで見える（ジャンプの後の傾きは一致する）。
   - 次のどれでも変わらない: 摩擦の有無、刻みを 1/4 にする、`ode15s`（可変刻み）への変更、`ExtrapolationOrder`、armature の回転子の初期速度指定（`w_specify`）、関節の速度ターゲット優先度、S2PS の `InputFilterTimeConstant`（provide モード）。→ ソルバや初期条件の問題ではなく、モデル構造（関節速度 → RMI → 反作用トルク → 関節トルク入力）の性質と見られる。
   - S2PS の `FilteringAndDerivatives`: 現状の `provide` と `zero` では、保持中に急なトルクステップを入れると dq が 205 rad/s ずれ、最大 1.6e4 rad/s のスパイクが出た。`filter`（1 次、1 ms）にすると、この 1 ケースでは差が 4e-4 rad/s に収まった（フィルタの遅れがジャンプと打ち消し合うと見られる）。ただし `filter` で時定数を変えると 0.11〜0.12 rad/s の差が戻り、乱数トルク列（1 ms／0.125 ms ごとに更新）では `provide` と大差なく、解決策にはならない。
   - 乱数トルク列（各軸 ±20% 定格、6 軸、base モデル）での dq 差: 1 ms ごとに更新すると J6 で RMS 0.088 rad/s（参照の最大 0.22 rad/s に対し）。J1〜J3 も参照の最大値と同程度の誤差になる。
   - **含意**: Phase 1 のテストが合格したのは、トルクが一定の窓（t=10 ms 以降）だけを見ていたため。トルクが変わる実データでは、1 ステップ予測の真値が「理想の剛体＋armature」から系統的にずれる。解析モデルを土台にする残差型 NSM の前提（真値 = 解析モデル＋接触）にも影響する。
   - 未解明: 「約 1 ms」の出どころ（S2PS の既定の時定数 1 ms と数値は一致するが、変えても効かない）。
2. **手首を開ループで強く駆動すると非現実的な速度になる。** J6 を定格トルク（15.9 N·m）で押すと、限界到達前に 680 rad/s まで加速し、衝突時に 1 サンプルだけ 4098 rad/s のスパイクが出た（位置は連続で、直後に 54 rad/s へ戻る）。J4/J5 も 12〜18 rad/s で、`p.qdMax`（約 7.9 rad/s）を超える。J1〜J3 も定格トルクで `qdMax` をやや超える（J1 5.9 vs 5.1、J3 7.0 vs 6.3）。
   - **含意**: Phase 2 の励振には、J2 版と同様に速度・位置のソフトバリアとトルク飽和が必須。リミット試験は手首のみ定格の 10% にした。衝突スパイクの原因（接触の剛性とソルバ）は未調査。
3. 検証の範囲は、3 軸・6 軸とも「可動域 ±60% 内の乱数姿勢」と「リミット近傍」のみ。**特異点（手首 J5 = 0 付近）や、可動域の端に近い姿勢での前進動力学の一致は未検証**。

## ゲート G1 の判定
- 腕 3 軸・6 軸とも、重力保持・前進動力学の短窓一致（**トルク一定の窓のみ**）・自由落下・リミット到達が合格 ✔。ただしトルク変化時のずれ（見つかったこと 1）が未解決で、**ゲート G1 は条件付き**
- 連成の影響: 3 軸で J1〜J3 の連成込みの前進動力学が一致している。手首を足した 6 軸でも同じ基準で合格。
- 生成時間の再確認は未実施（Phase 0 の見積もりのまま。テスト全体は 1231 s）。

## 次に決めること（ユーザー判断）
見つかったことの 1 は、Phase 0 で決めた「armature あり・ode14x のまま」の前提に関わる。
1. armature の表現を変える（RMI を使わない別表現。速度も約 3 倍になる見込み）。ただし、親資産が RMI にした理由（他軸への慣性の漏れ）の検証が要る。
2. 現状のまま進め、プラントの「理想からのずれ」を真値の一部として受け入れる（解析モデル側に 1 ms 先行のトルクを入れて合わせる補正も考えられる。ただし未検証）。
3. 原因をさらに調べる（Simscape のドキュメント、RMI の導出）。
