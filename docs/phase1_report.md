## 見つかったこと
1. **トルクが変化すると速度が瞬間的にジャンプする。原因は Solver Configuration の自動フィルタ（`FilteringTimeConstant`、既定 1 ms）。** 当初「初期過渡」と書いたが、t=0 に限らない。切り分け（`spike/phase1_transient.m`、`phase1_kick.m`、`phase1_stepcheck.m`、`phase1_pwc.m` ほか。6 軸）:
   - armature なしのモデルは解析モデルと 1e-10 rad/s で一致。armature（RMI）ありのときだけ発生。起きるのは正味トルクが変わった瞬間。
   - ソルバ（ode15s 含む）、刻み、`ExtrapolationOrder`、摩擦、rotor の初期速度、S2PS の時定数では変わらない。
   - **原因**: Solver Configuration の `AutomaticFiltering = on`、`FilteringTimeConstant = 0.001`。RMI の 1-D/3-D 接続には自動フィルタが必須（`AutomaticFiltering` を off にすると「フィルター処理が必要な 1 次元/3 次元接続が見つかりました」エラー）。rotor の反作用トルクの加速度が 1 ms の 1 次遅れを通る。
   - 遅れを入れたモデル `M_l·ẇ = τ − J_arm·ẇ_f`（`ẇ_f` は `ẇ` の 1 次遅れ、時定数 T）から、トルク変化 Δτ に対する速度ジャンプは **Δω = Δτ·T·J_arm / M²**（M は実効慣性、M_l = M − J_arm）。J4/J5/J6 の実測（0.00741 / 0.0225 / 0.12 rad/s）が予測と 1% 以内で一致（T = 1 ms）。
   - `FilteringTimeConstant` を 1 ms → 0.5 / 0.2 / 0.1 ms にすると、ジャンプは比例して 0.5 / 0.2 / 0.1 倍になる（実測）。
   - 帰結: 遅れが**隠れ状態**（`ẇ_f`）になるため、(q, dq, τ) から次状態が決まるという NSM の前提が崩れる。小さい時定数にする必要がある。
   - **対策（確認済み）**: 時定数を小さくし、**可変刻み `ode15s`（MaxStep = 125 µs）** を使う。`ode14x`（固定刻み）では時定数 5e-4 以下で長い実行が発散するが、`ode15s` では 1e-5、1e-6 でも安定。乱数トルク列（6 軸、各軸 ±20% 定格、40 ステップ、1 ステップごとに更新）での dq 差（RMS、J6）:

     | 設定 | J6 の dq 差 RMS [rad/s] | 備考 |
     |---|---|---|
     | ode14x、1e-3（現状） | 0.08〜0.09 | 参照の最大は 0.06〜0.2 |
     | ode15s、1e-3 | 0.092 | |
     | ode15s、1e-5 | 9.4e-4 | 約 100 倍改善 |
     | ode15s、1e-6 | 9.4e-5 | |

     3 軸の `ode15s`、1e-5 でも同様（J3 の最大差 2.6e-4 rad/s）。
   - **速度も改善**: J2 自由落下 5 s（6 軸）が ode14x 121 s → ode15s（1e-5）13.6 s（約 9 倍）。J6 のリミット押し込み 2 s が 8.0 s。ただし 1 姿勢・各 1 回の計測で、動的な負荷が大きいシナリオでは差が縮む可能性がある。
   - **入力の与え方**: 厳密なゼロ次保持（ステップが eps 幅）は、時定数が小さいと微分が非有限になり失敗する。ソルバ格子上の標本値を渡す（`simSa(…, onGrid=true)`、格子間は線形補間）と安定。この場合の「トルク（t_k）が x_k → x_{k+1} のどの区間に効くか」の定義は、Phase 2 で決める必要がある。
   - 参考にした資料: [Simulink-PS Converter](https://www.mathworks.com/help/simscape/ref/simulinkpsconverter.html)（時定数の既定値は 0.001 s）、[Rotational Multibody Interface](https://www.mathworks.com/help/simscape/ref/rotationalmultibodyinterface.html)（フィルタには言及なし。Solver Configuration の項目は実機モデルの `get_param` で発見）。
   - 実装: `buildSaPlant` に `opts.solver`（`'ode14x'` 既定／`'ode15s'`）と `opts.filterTc` を追加（既定は従来どおり。未切替）。`simSa` に `onGrid` を追加。
2. **手首を開ループで強く駆動すると非現実的な速度になる。** J6 を定格トルク（15.9 N·m）で押すと、限界到達前に 680 rad/s まで加速し、衝突時に 1 サンプルだけ 4098 rad/s のスパイクが出た（位置は連続で、直後に 54 rad/s へ戻る）。J4/J5 も 12〜18 rad/s で、`p.qdMax`（約 7.9 rad/s）を超える。J1〜J3 も定格トルクで `qdMax` をやや超える（J1 5.9 vs 5.1、J3 7.0 vs 6.3）。
   - **含意**: Phase 2 の励振には、J2 版と同様に速度・位置のソフトバリアとトルク飽和が必須。リミット試験は手首のみ定格の 10% にした。衝突スパイクの原因（接触の剛性とソルバ）は未調査。
3. 検証の範囲は、3 軸・6 軸とも「可動域 ±60% 内の乱数姿勢」と「リミット近傍」のみ。**特異点（手首 J5 = 0 付近）や、可動域の端に近い姿勢での前進動力学の一致は未検証**。

## ゲート G1 の判定
- 腕 3 軸・6 軸とも、重力保持・前進動力学の一致（トルク一定、毎ステップ変化の両方）・自由落下・リミット到達が合格 ✔（既定を ode15s＋filterTc 1e-5 に切り替えて 12 件合格）。**ゲート G1 合格**
- 連成の影響: 3 軸で J1〜J3 の連成込みの前進動力学が一致している。手首を足した 6 軸でも同じ基準で合格。
- 生成時間の再確認は未実施（Phase 0 の見積もりのまま。テスト全体は 1231 s）。

## 決定（2026-10-12、ユーザー）
既定を **ode15s＋filterTc 1e-5** に切り替えた（armature の RMI は維持）。Phase 0 の「armature あり・ode14x のまま」を置き換える。

## 次に決めること
- Phase 2 で、トルク t_k が x_k → x_{k+1} のどの区間に効くかの定義（プラントへは 8 kHz 格子上の標本値＋線形補間で与えている）、出力の 8 kHz 格子への落とし方（`OutputOption`＝`SpecifiedOutputTimes` か補間）、可変刻みでの再現性（ビット一致）を決める。
- 生成時間の見積もりを ode15s で取り直す（Phase 0 の 24〜26 倍は ode14x の値。ode15s では自由落下で約 9 倍速かったが、動的な負荷が大きいシナリオは未計測）。
