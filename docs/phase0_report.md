# Phase 0 レポート — 基盤とスパイク（issue #3）

実施日: 2026-10-11 / MATLAB R2025a / 親資産 `robotArmSurrogate-matlab`（参照のみ）
スクリプト: `config/sa_config.m`、`spike/phase0_build.m`（プラント生成）、`spike/phase0_measure.m`（実測）

## 方式
J2 版の方式 A（親の `writeC8URDF` 出力を後処理し、可動にしない joint を fixed 化して `smimport`）を一般化。先頭 `nAx` 軸を可動、残りは 0 rad で固定。可動軸は `joint1..nAx` のままなので、親の `addC8Actuation/Armature/Friction`（`nJoints=nAx`）をそのまま適用できる（J2 版のような改名は不要）。8 kHz 固定ステップ `ode14x`。

## データ規模の見積もり（暫定）
J2 版は 1 kHz で 2.86M 遷移（約 2,860 s のシミュレーション）で、実行約 5.4 倍・約 4 時間だった。同じシミュレーション時間を 6 軸で生成すると、上の実行倍率（約 10〜26 倍）では **約 8〜21 時間**になる。6 軸は次元が増えるため、J2 と同じ遷移数では被覆が薄く、さらに増える。**J2 の 5.4 倍より大幅に遅い**のが最大の問題で、原因は未調査（ソルバ反復、DAE の規模など）。

## ゲート G0 の判定
- 3 軸・6 軸とも 8 kHz で発散なく動く ✔（保持・自由落下・リミット接触）
- 生成時間・メモリの見積もり: **粗い見積もりのみ** △（上記の注意のとおり、計測点が少ない）

## 実行速度の切り分け（腕 3 軸、保持 2 s、各 2 回目の時間）
スクリプト: `spike/phase0_speed.m`（`phase0_build` に `armature`/`friction`/`suffix` オプションを追加）。

| ケース | 2 s の実行時間 | 実時間倍率 | 所見 |
|---|---|---|---|
| 現状（armature 有・摩擦有・ode14x） | 21.4 s | 10.7 | 基準 |
| armature 無し | 15.0 s | 7.5 | RMI（armature）で約 30% |
| 摩擦無し | 25.0 s | 12.5 | 摩擦は遅さの原因ではない |
| `NumberNewtonIterations`=2 / 3 | 34.2 / 47.3 s | 17.1 / 23.7 | 増やすと遅くなるだけ（既定の 1 が最良） |
| Rapid Accelerator | — | — | **ライセンス非対応**（ノーマルモードで実行され無効） |

追加実験（armature 無しモデル、保持 2 s）:

| ソルバ | 時間 | 倍率 |
|---|---|---|
| ode14x | 18.3 s | 9.1 |
| ode1be | 8.5 s | 4.2 |
| ode3 / ode4 | 6.2 s | 3.1 |

- armature 無しなら陽的ソルバ（ode3）が使え、**ode14x より約 3 倍速い**。自由落下 5 s（リミット接触あり）でも ode14x 37.1 s → ode3 7.9 s、軌道差は最大 0.005°、発散なし。
- 1 回の `sim` 呼び出しに**固定費が約 3 s**（0.1 s の実行で 3.55 s）。短いシナリオを多数回すと効く。
- 今回の測定は 3 軸・1 姿勢・各ケース 1 回。6 軸の再測定はしていない。

## 結論と次の一手
- 遅さの主因は **armature の RMI が DAE を作り、陰的ソルバ ode14x を強いること**。ソルバ設定の調整だけでは改善しない。
- armature を RMI を使わずに表現できれば、ode3 で約 3 倍速くなる見込み（armature 有り ode14x の 7.5〜10.7 倍 → 3 倍前後）。ただし armature は J2 の実効慣性 6.09 のうち 2.29 を占め、外せない。親資産は、リンクへ畳み込むと上流軸へ慣性が漏れるため RMI にした（`addC8Armature` のコメント）。
- 代替案（未実装・未検証）: ① リンクの慣性テンソルへ畳み込む際に、ロータ軸回りの非対角成分も含めて正しく表現できないか検討 ② Simscape の Common Gear Constraint（親資産が幾何が煩雑で断念）③ 陽的に解ける別表現。いずれも Phase 1 の物理検証（RNEA との一致）で確認が必要。

## 決定（2026-10-12、ユーザー）
**armature あり・ode14x のまま進める**（生成に丸一日かかることを許容）。RMI の代替表現は試作しない。
- 理由: 真値の構造（親資産と同じ RMI）を変えずに Phase 1 へ進める。J2 版と同じ真値の作り方を保てる。
- 帰結: 生成は 6 軸で実時間の約 24〜26 倍（暫定）。長時間生成は J2 版と同様に別プロセス・シナリオ単位キャッシュ・分割ワーカーで行う。メモリはワーカー 1 本あたりを Phase 3 前に実測する。1 回の `sim` に約 3 s の固定費があるため、シナリオは極端に短くしない。
- 速度改善の再検討: 生成規模が確定した時点で、必要なら armature の代替表現を再評価する（本決定は撤回可能）。
