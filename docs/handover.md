# 引継ぎ資料 — J2 単軸版から 6 軸版へ

作成: 2026-10-11 / 引継ぎ元: [j2-state-data-gen](https://github.com/yk142/j2-state-data-gen)（J2 単軸の学習データ生成〜学習・評価まで完了）、[sixAxisArmSurrogate](https://github.com/yk142/sixAxisArmSurrogate)（自前 RNEA の 6 軸サロゲート。2026-09-27 に総括済み）

## 1. 目的の再確認
EPSON C8-A901S の 6 軸を対象に、**Neural State Model（次時刻状態予測）** の学習データを生成し、学習・評価する。J2 単軸版で「データ生成 → 出力 → 学習 → 閉ループ評価」が実用的な精度で通ったため、6 軸へ展開する。

## 2. 引継ぎ元の成果（要点）
### j2-state-data-gen
| 項目 | 内容 |
|---|---|
| 真値 | URDF から Simscape（`smimport`）、8 kHz 固定ステップ `ode14x`。他軸は URDF 後処理で fixed 化。親資産 `robotArmSurrogate-matlab` の `c8_params`・アクチュエータ・摩擦・励振等を **path 参照**（コピーしない） |
| データ | 394 シナリオ、1 kHz で 2,856,681 遷移。励振（BLN/chirp/step/micro/freefall）、姿勢保持（PD+FF）、PTP ベンチマーク、リミット接触 |
| 1 kHz 変換 | 状態は瞬時値の間引き、トルクは区間平均（フィルタなし。遷移データのため） |
| 出力 | HDF5 / v7 mat。h5py から (N,d)、ID は 0 始まり |
| 再現性 | キャッシュなし再生成で 10/10 ビット一致 |
| 学習 | Python + PyTorch。純粋 MLP と、解析モデル（RK4）＋NN 残差の `ResidualNSM` |
| 結果 | 残差型: 接触なしで解析モデルと一致、PTP 閉ループ 0.007°（純粋 NN 0.086°）。**1 シード・1 設定のみ** |

### sixAxisArmSurrogate
- 自前 RNEA（修正 DH）の 6 軸真値。NN は摩擦係数のみ学習するグレーボックス
- 結論（#40）: 支配方程式が厳密に解ける問題では、NN による高速化は RNEA＋numba に勝てない。NN が有効なのは、解析で説明できない部分（接触・未知の摩擦）
- 教訓: 角度の巻き付き（周期性）で真値とサロゲートの絶対角度が食い違う失敗ケース、摩擦は関数形固定・係数のみ学習、損失は成分ごとに標準偏差で正規化

## 3. 再利用する方針・手順
1. **作業サイクル**: issue → ブランチ → 作業 → 報告 → ユーザー指示でコミット＋issue 投稿 → ユーザー指示で PR → 承認。main へ直接 push しない。**PR の base は main にする**（J2 版で積み上げ PR が main に入らなかった）
2. **要件 → 計画 → 実装**の順。検証ゲートを各フェーズ末尾に置く
3. **データ生成**: シナリオ単位キャッシュ（中断再開）、シードで決定的な Sobol 初期状態、split はシナリオ単位（リーク防止）、正規化統計は train のみ、8 kHz 生データを保存してから間引く
4. **評価**
   - **全長の開ループ再生で評価しない**（不安定平衡まわりは正確なモデルでも発散）。閉ループ（制御器＋モデルをプラントに）と短い窓で評価
   - 1 ステップ誤差は物理量（加速度換算）で出し、目標の標準偏差と「状態を変えない」基準線を併記
   - **弱い基準線との倍率を主張しない**（接触の非弾性ストッパ解析モデルは無視するより悪かった）。比較は強い基準線に対して
   - 接触は動的／静止押し付けに分けて見る（動的は件数 0.36% で誤差の約 90%）
5. **学習**: 解析モデル（既知の物理）を土台に NN は残差のみ。最終層ゼロ初期化。損失は接触なし用に絞ると接触を学べない（要設計）。早期終了の patience を大きくする。学習は `nohup` でバックグラウンド
6. **報告**: 評価結果は PNG を `reports/issue-N/` にコミットし、SHA 固定の raw URL で issue コメントに埋め込む。**コミット後に rebase するとコメントの URL の SHA が変わる**ので注意
7. **MATLAB 運用**: 8 kHz は実時間の約 5〜6 倍。Parallel Computing Toolbox は未許諾（直列）。Deep Learning / System Identification / Statistics & ML Toolbox は使用禁止。ワーカー 1 本で約 3.7 GB。`clear functions` の忘れによる古い関数キャッシュに注意

## 4. 6 軸で変わること（J2 版の前提が崩れる点）
| 項目 | J2 | 6 軸 |
|---|---|---|
| 状態・入力 | (q, dq)、τ の 1 次元 | 12 次元状態、6 次元トルク |
| 動力学 | `M·ddq = τ + mgL sinθ − …`（スカラー） | 質量行列 M(q)、コリオリ、姿勢依存の重力（軸間連成） |
| 解析モデル（残差の土台） | スカラー式 | RNEA（`c8RNEA` 等の親資産、または自前）＋摩擦 |
| カバレッジ | 3 次元（θ, θ̇, τ）の占有率 | 次元の呪い。占有率は使えない。軸別・ワークスペース別・PTP 包含などへ |
| 不安定性 | θ=0 の倒立点 | 姿勢で変わる。評価は閉ループ |
| 角度 | 可動範囲内のみ | 巻き付き・特異点（手首）の扱い |
| リミット接触 | 1 軸 | 6 軸分。接触シナリオの設計が増える |

## 5. 未解決・確認が必要な事項
1. **【決定 2026-10-11】真値**: Simscape/URDF（C8-A901S の実機諸元に近い。J2 版と同じ。重い）を真値とし、RNEA を残差型の解析モデル（土台）に使う。sixAxisArmSurrogate の自前 RNEA（諸元は実機と非一致）は真値に使わない
2. **【決定 2026-10-11】段階**: 腕 3 軸（J1〜J3、手首は fixed）→ 6 軸。連成と生成時間を 3 軸で確認してから手首を足す
3. **モデルの形**: 6 軸まとめて 1 つのモデルか、軸ごとのヘッドか。入力は sin/cos か
4. **J2 版の未解決**: 結果が 1 シード・1 設定。dual 損失の出力単位の修正は未検証。動的接触が少ない（#16）、静止押し付けが 93.6%（#17）、バリア端の大トルクの偏り（#14）
5. **実用性の確認**: 学習済みモデルを制御ゲイン最適化などの実用途に使った検証は未実施
6. **データ規模**: J2 は 394 シナリオで約 4 時間（8 kHz）。6 軸は実行時間が増える。生成時間とメモリの見積もりが先に必要
7. **親資産への依存**: `robotArmSurrogate-matlab` は path 参照のみ（変更しない）。6 軸でも同様とするか
