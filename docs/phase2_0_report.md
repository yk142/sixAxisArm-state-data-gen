# Phase 2-0 レポート — ode15s 運用の取り決め（issue #7）

実施日: 2026-10-12 / MATLAB R2025a。6 軸プラント（既定: ode15s、MaxStep 125 µs、RelTol 1e-6、AbsTol 1e-8、filterTc 1e-5）。
スクリプト: `spike/phase2_scenario.m`、`phase2_scenario_1k.m`、`phase2_run.m`、`phase2_ref.m`、`phase2_interval.m`、`phase2_repro_once.m`

シナリオ: 6 軸、可動域の ±50% 内の乱数姿勢から、重力補償＋(a) 各軸 ±15% 定格の正弦和（5〜40 Hz、滑らか）または (b) 1 ms ごとに一定の乱数トルク（±10% 定格、1 kHz 制御器を想定）、0.5 s。どちらも **1 シードずつ**。

## 1. 出力の 8 kHz 格子への落とし方
| 方式 | 点数 | 参照（FOH 入力の ode45）との dq 最大差 [rad/s] | 実行時間 |
|---|---|---|---|
| 既定出力 → 線形補間 | 55,895（ソルバの刻み） | 3.6e-5〜3.4e-4 | 23.1 s |
| `OutputOption=SpecifiedOutputTimes`（格子を指定） | 4,001（格子と一致） | 同じ（3.6e-5〜3.4e-4） | 17.5 s |

→ **`SpecifiedOutputTimes` を使う**。精度は補間と同じで、出力が格子に厳密に一致し、データ量も実行時間も小さい。（既定出力が 0.5 s で 5.6 万点あるのは、入力が 8 kHz ごとに折れ線のため、ソルバが折れ点ごとに刻みを細かくするためと推測。未確認）

## 2. 再現性
同一入力・同一モデルで、出力（q, dq）が**ビット一致**した: 同一セッションで再実行、モデルを閉じて読み込み直し、別プロセス（`matlab -batch`）の 3 通り。
- 確認範囲は 1 シナリオ・1 台のマシン。MATLAB のバージョンや CPU が変わったときは未確認。
- Phase 3 の再現確認（キャッシュなし再生成）で、全シナリオについて確認する。

## 3. トルク τ_k の定義（1 kHz の遷移 x_k → x_{k+1}）
プラントへは 8 kHz 格子上の標本値を渡し、格子間は線形補間される。1 kHz の区間（8 ステップ）の入力を、解析モデル（RK4、区間内トルク一定）に与えて x_{k+1} を予測し、プラントの x_{k+1} との dq 差（RMS、軸ごと）を比べた。

| τ_k の定義 | (a) 滑らかな正弦和 J6 | (b) 1 kHz 区間一定 J6 |
|---|---|---|
| 始点の標本値 τ(t_k) | 3.0e-3 | 5.4e-3 |
| **区間の台形平均**（FOH 入力の平均） | **3.8e-4** | **2.1e-3** |
| 左端 8 標本の単純平均 | 7.1e-4 | 5.4e-3 |
| 終点の標本値 | 2.3e-3 | 4.8e-2 |
| （参考）FOH 入力そのままを積分 | 5.3e-5 | 7.4e-4 |
| （参考）dq の 1 ms 変化の RMS | 1.0e-2 | 3.9e-2 |

→ **τ_k = 区間 [t_k, t_{k+1}] で実際にプラントへ入った 8 kHz 入力（線形補間）の平均（台形則）** と定義する。始点値より 7〜8 倍（滑らか）、2.6 倍（区間一定）小さい。J2 版の「トルクは区間平均」と整合する。
- 1 kHz 区間一定の入力でも、境界で次の値へ移る立ち上がりが 1 ステップに掛かるため、単純平均（左端 8 標本）は始点値と同じになり、立ち上がりの寄与（台形平均の 1/16）を捉えない。**生成側では台形平均を記録する**。
- 台形平均でも、区間内のトルクの形（折れ線）を無視する分の誤差が残る（J6 で dq の 1 ms 変化の 5%）。残差型 NSM が学ぶ対象に含まれる。

## 4. filterTc の追加検討
(b) の「FOH 入力そのまま」の誤差 7.4e-4（J6）は、filterTc 1e-5 の残りの遅れ（予測 Δω = Δτ·T·J_arm/M²、Δτ ≈ 3 N·m で約 1.9e-3 の最大ジャンプ）と同程度。filterTc を 1e-6 にすると、この誤差は **7.4e-5 に 10 分の 1** になった（実行時間は同程度: 26.1 s → 18.0 s。初回実行のコンパイル分が混ざる）。
- 台形平均の誤差は 2.1e-3 → 1.4e-3 とあまり変わらない（区間内の形の無視が支配的）。
- **決定（ユーザー、2026-10-12）**: 既定を 1e-6 に切り替えた。`test_sa_plant`（3 軸・6 軸、12 件）を 1e-6 で再実行して**全件合格（448 s。1e-5 では 415 s）**。リミット到達・自由落下・乱数トルク列を含む。
- 1e-6 でも 1 シード・1 台の確認。さらに小さい値（1e-7 など）は試していない。

## 5. 生成時間（ode15s と旧設定の比較）
同一シナリオ (a)（0.5 s、8 kHz で折れ線の入力）の 2 回目以降の実行時間:

| 設定 | 実行時間 | 実時間倍率 | dq の参照との最大差 [rad/s] |
|---|---|---|---|
| ode14x、filterTc 1e-3（旧） | 15.7 s | 31 | 3.9e-3〜3.4e-2 |
| ode15s、filterTc 1e-5（現状、格子出力） | 16.8〜18.3 s | 34〜37 | 3.6e-5〜3.4e-4 |

→ **動的な励振では、ode15s に速度の優位はない（ほぼ同じ）**。精度は約 100 倍よい。Phase 1 で報告した「自由落下 5 s が 121 s → 13.6 s」は、トルク一定の区間（ソルバが大きな刻みを取れる）での値で、**励振では当てはまらない**。
- 生成時間の見積もり（6 軸、実時間の約 31〜37 倍、1 台直列）: J2 版の規模（約 2,860 s のシミュレーション）なら約 25〜30 時間。6 軸は次元が増えるため、実際はこれ以上。Phase 0 の「約 24〜26 倍」より悪い（励振が動的なため）。
- 1 シナリオ・1 回の計測。トルクの帯域や姿勢で変わる。

## まとめ（取り決め案）
1. 出力は `SpecifiedOutputTimes`（8 kHz 格子）。
2. 再現性は、1 シナリオでビット一致を確認。全シナリオでの確認は Phase 3。
3. τ_k は区間の台形平均。
4. filterTc は **1e-6 に切替済み**（テスト 12 件合格）。
5. 生成時間は実時間の約 31〜37 倍。**約 1 日以上かかることは許容（ユーザー）**。規模の目標は、時間（ワーカー数、メモリ）を見て Phase 3 で決める。
