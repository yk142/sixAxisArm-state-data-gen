## 検証結果
- `test_sa_pipeline`（8 件）: 台形平均がブロックごとの `trapz/8` と一致、区分線形入力（FOH）で厳密（区間中点の値）、非整数の間引き率はエラー、統計が train のみ（val / test / benchmark を 5 倍にしても不変）、マニフェスト、キャッシュ不一致の検出、`atLimit` の位置、検証関数の不合格検出（NaN・トルク超過・PTP が train・シード重複）
- `test_sa_gen`（3 件）: shard 1/2 と 2/2 の担当が重ならない、全件揃った後の組み立てがシミュレーションなし（20 s 以内）、キャッシュを 1 本消して別モデルで再生成するとビット一致、1 kHz の状態が 8 kHz の瞬時値の間引きと一致、実データで検証関数が合格
- **ゲート（small 20 本）**: 2 shard で生成（7 分 42 s）、組み立て、検証が通った。20 シナリオ、41,686 遷移（train 17 / val 0 / test 1 / benchmark 2 シナリオ）、データセット 5.1 MB、キャッシュ 28 MB
- 解析モデル（`saFwdDyn`）との 1 ステップ整合の残差比（加速度換算、RMS / 目標の標準偏差、J1〜J3）: **[2.6%, 1.2%, 2.1%]**（small 20 本から 2,000 点）

## 判断・発見
1. **τ の区間平均は台形平均**。J2 版の単純平均（区間先頭側の 8 点）と違い、FOH で補間した実印加トルクの区間平均を厳密に表す（区分線形入力でテストした）。区間先頭の瞬時値は `tauInst` に残す
2. **キャッシュは double**（J2 版は single）。再開の再生成がビット一致することを確認できた（single だと丸めが比較に入る）。small の 20 本（約 40 s）で 28 MB なので、full（1,290 s）は約 0.9 GB の見込み
3. **shard の担当は表の位置で決める**（`mod(位置-1, n) == i-1`）。表の順で振るので重ならず、中断後の再実行でも同じ担当になる
4. **モデル構築（励振＋閉ループの 2 モデル）は、`genSaDataset` を呼ぶたびに 1 回**行う（個別の時間は未計測。数十秒規模）。中断・再開が多いと無視できなくなる
5. **マニフェストの `repoCommit` は HEAD の SHA だけで、未コミットの変更は含まない**。full を回す前に、コードをコミットしておく（または SHA に加えて差分の有無を記録する）。3-2 の最初に対応する
6. **small には val シナリオが無い**（n < 8 のパターンは val が 0 本。Phase 2-3 の発見 5）。small は動作確認用。full の split は Phase 2-3 で確認済み
7. 初期条件の警告（armature_N.w の拘束競合）は生成中も出る。無害（Phase 2-4 の発見 4）

## 限界
- ここで通したのは small（20 本）。full の総時間・メモリ・キャッシュ容量は 3-2 で実測する
- 解析モデルとの整合の残差比は small の抜き取りの値で、full での値は 3-3 で出す。接触（atLimit）を含む遷移は、ソフトバリアだけの間は 0 件（small の nearlimit も 0）
- カバレッジ評価・全件の再現性・HDF5 は 3-3 以降
