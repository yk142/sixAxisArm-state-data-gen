# Phase 5-1: 評価基盤の固定（G-bench v1、判定式の統一、評価器のバッチ化）（issue #89）

## G-bench v1（固定した評価条件）
| 項目 | 値 |
|---|---|
| 真値 | 弾性つき Simscape（#71、f=20 Hz）。ステップ 2°、姿勢 P0、1 軸ずつ（6 軸） |
| ペイロード | 0 / 1 / 3 / 5 / 8 kg（arm6 の [0 0 0.05] m） |
| ゲイン | wn 60 / 100 / 150 × ζ 0.5 / 1 / 2 / 3（12 点）。ζ=3 は本 issue で追加生成（`payload_eval6_el20_z300_p*.h5`、90 本） |
| 評価器 | `eval_payload_el.py --batch --iters 1 --wn-min 60`、2 慣性解析はサブステップ 8 |
| 判定（水準 G） | ΔOS ≤ 2 pt、Δ整定 ≤ 10% **かつ** ≤ 20 ms、ステップ区間位置誤差 ≤ 0.1°、選択ゲインの整定悪化 ≤ 10%、選択ゲインの真値 OS 最大 ≤ 7% |
| 集計 | `summarize_payload.py --data data/eval/gbench89/pl*/payload.json` |

## 変更点
1. **Δ整定の判定を「かつ」に統一**（`summarize_payload.py`・`summarize_sens.py`。以前のコードは「または」）。過去の報告（#61〜#85）を新しい式で集計し直すと、変わるのは #81 の基準（k=1、サブステップ 4。Δ整定 8 ms・14.8%）の ○ → × の 1 件だけ。#65〜#77 の ○（解析・B・2 慣性解析）は全て ○ のまま。
2. **最適ゲインの判定を「一致」から「性能低下」に変更**（ユーザー判断）。モデルが選んだゲイン（OS ≤ 5% で整定平均最小）を真値で動かしたときの、真値の最適に対する整定の悪化 ≤ 10%（Δ整定の許容と同じ）と、真値の OS 最大 ≤ 5 + 2 %（OS 制約 + ΔOS の許容）。一致は参考として残す。
   - 理由: ζ を 3 まで広げても、真値の最適は 5 ペイロード中 4 で格子の端だった（下表）。各 wn では ζ を上げるほど整定が遅く、「OS ≤ 5% を満たす最小の ζ」が最良になり、wn は大きいほど速い。最適は OS の境界上の最大 wn に来る構造で、格子を広げても端に張り付きやすい。
   - 区別力の確認: #85 の B 型（3 kg で 60/2 を選択、真値は 100/2）は整定悪化 112% で ×。パラメータ誤差の 2 慣性（4/4 一致）は 0%。
3. **評価器のバッチ化**: 同じペイロードの全ゲイン×6 軸（72 行）を 1 回の閉ループで計算（行ごとに Kp・Kd）。複数 HDF5、ζ・ペイロードの絞り込みに対応。1 グループの結果は #77 と完全一致（OS・誤差とも同値）。
